# Contributing

Use Issues to discuss questions, report bugs, and propose features. Describe the user problem, expected outcome, and any acceptance criteria. Include the application version and reproduction steps for bugs.

Propose documentation and SPEC changes through pull requests. Keep proposed behavior distinct from shipped functionality. Link related issues and milestones.

Everything in this repository is public. Remove credentials, customer/device identifiers, sensitive configurations, and internal logs before posting. Team write access is managed by repository administrators.

For releases, update CHANGELOG.md with the version, create the matching GitHub Release, and attach verified platform binaries with SHA-256 checksums and installation/compatibility notes. Keep binaries in release assets, not Git. Publish actual tested artifacts only.
