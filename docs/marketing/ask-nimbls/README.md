# nimbls — Website kit guide

This kit contains a product website and reusable marketing resources. It is not the nimbls application installer.

## Open and share

Download and extract the whole kit. Open `index.html` directly for offline reading, or use `Start Website.command` (macOS), `Start Website.bat` (Windows), or `sh start-website.sh` (Linux). Launchers require Python 3. Keep the launcher window open while browsing; Ctrl+C stops it. Share the ZIP or an approved hosted URL, not a loopback address.

## Reading paths

- Customers: Use cases → Capabilities → Development preview → Roadmap → share a workflow need.
- Sales and partners: Resources → Visual Library → editable diagrams, feature briefs and presentation scripts.
- Product reviewers: Development preview → dated evidence and capability inventory → milestone completion conditions.

The development preview distinguishes implemented source, fresh checks and prior live trials. Planned milestone outcomes and unscheduled candidates are separate. No packaged product release is claimed.

## Roadmap

Concepts and milestone outcomes come first. Expand the optional date planner to model 10 or 15 working days per stage against bundled 2026–2027 Taiwan government calendars. These are effort scenarios, not validated estimates or delivery commitments. Company-specific leave and emergency closures are not included. Total and monthly views have SVG downloads; Markdown includes milestone deliverables.

The evolution diagram has a readable mobile list and an editable SVG download. The Visual Library also retains the undated reference poster, labeled as an effort scenario.

## Resources

`resources.html` is the sales/marketing entry; `visuals.html` holds diagrams. `assets/current-capabilities.md` and `assets/development-evidence.md` are dated capability/evidence inventories. `assets/milestone-evolution.svg` explains concepts and capabilities. Actual development screenshots are labeled separately from historical reconstructions and planned workflow diagrams.

The kit contains all website HTML pages, assets, the editorial content catalog and launcher files. Complete ZIPs exclude themselves and each other. In an extracted kit, the complete-kit download needs the original ZIP alongside the pages; individual downloads still work.

## Maintaining the site

Serve the HTML pages, assets and README together. Keep claims aligned across pages, Markdown, diagrams and `feature-content.json`; editing the catalog alone does not rebuild HTML. Update script/style content hashes and refresh the download archives after changes. Use a supported hosting service for public production hosting; the local launcher is a preview server.

## Troubleshooting

Missing Python: open `index.html` directly, or ask IT to install Python 3. Missing images: extract the whole ZIP with its assets folder. Preview address unavailable to a colleague: share the ZIP or approved hosted URL. On macOS, follow organizational security prompts; do not bypass a security block.

Development code name. Preserve all source dates, evidence limits, planned labels and synthetic-data captions when reusing materials.
