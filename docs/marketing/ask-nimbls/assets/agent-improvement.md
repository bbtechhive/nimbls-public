# Agent Improvement Review

**Learn from the work. Improve the next run.**

Status: planned capability, not released functionality. POC 5. Delivery dates TBD. nimbls remains a development code name.

## Standard feature card

| Field | Description |
| --- | --- |
| Audience | Agent owners reviewing quality and consistency |
| Customer problem | Repeated errors are hard to fix without knowing which inputs, instructions, and results produced them. |
| Capability | Ask nimbls to inspect an agent’s retained execution evidence and propose a targeted change. Compare results before adopting the revised approach. |
| Benefits | Understand recurring failures; Make specific, reviewable changes; Measure improvement against real cases |
| Deliverable | A review explaining the proposed change, before/after results, and remaining limitations. |
| Prerequisites | Queryable work history, retained evidence, editable agent settings, and representative evaluation cases. |
| Proof required | Show whether the target case improves and whether known-good cases regress; retain input/configuration context for comparison. |
| Scope and limits | This is evidence-based refinement, not automatic self-improvement or model training. Missing history may prevent a reliable conclusion. |

## Customer scenario

> This agent missed an important event. Review its work and help me improve it.

An operator supplies a known missed event. Ask nimbls examines the relevant work, suggests a change to the reporting instructions, and compares the revised behavior on the missed case and previously successful cases.

## Workflow

1. **Review:** Inspect execution evidence.
2. **Propose:** Identify a targeted change.
3. **Compare:** Run representative cases.
4. **Decide:** Keep evidenced improvements.
