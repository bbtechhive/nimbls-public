# Scheduling & Automation

**Set the task. Keep it working.**

Status: planned capability, not released functionality. Milestone 1 · Feature 3. Delivery dates TBD. nimbls remains a development code name.

## Standard feature card

| Field | Description |
| --- | --- |
| Audience | People repeating the same checks and reports |
| Customer problem | A useful reporting workflow still depends on someone remembering to start it every day. |
| Capability | Schedule a tested agent and inspect each outcome. Adjust, pause, resume, or cancel its schedule without confusing the schedule with an active execution. |
| Benefits | Reduce repeated instructions; Keep routine work organized; See failures and skipped work clearly |
| Deliverable | A saved daily schedule with next due time and visible execution outcomes. |
| Prerequisites | Saved agent and working dependencies; application running and computer awake when due. |
| Scope and limits | Missed occurrences are not caught up. Pausing or cancelling a schedule does not stop an already running task. |

## Customer scenario

> Run this report every morning at 8 a.m. in our saved timezone.

After refining the daily report, an operator saves a schedule, checks the next due time, and inspects the following execution. A failed run remains visible even when an older report is available.

## Workflow

1. **Validate:** Accept a useful result.
2. **Schedule:** Set time and timezone.
3. **Execute:** Use a fresh session.
4. **Inspect:** Review each outcome.

## Three-minute demo outline

- **0:00–0:30:** Explain the customer problem and show the scoped request.
- **0:30–2:00:** Walk through the four workflow steps using a prepared representative case.
- **2:00–2:40:** Inspect the deliverable and its evidence: Verify daily dispatch, fresh sessions, overlap skips, no catch-up, schedule controls, Stop, and Quit.
- **2:40–3:00:** Explain prerequisites and limits: Missed occurrences are not caught up. Pausing or cancelling a schedule does not stop an already running task.

These are presentation slots, not execution-speed claims. Label mockups and pre-run examples. No validated runtime demo is implied.
